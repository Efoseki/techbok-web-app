# API specification — foundation and Phase 2A

Base URL: `http://localhost:8000/api/`  
Authentication: `Authorization: Bearer <access_token>`

## Authentication
- `POST auth/token/` — body `{ "username": "admin", "password": "..." }`; returns access and refresh JWTs.
- `POST auth/token/refresh/` — body `{ "refresh": "..." }`.
- `GET auth/me/` — current user profile and branch memberships.

## Branches
- `GET branches/` — system administrators see all; other users see branches where they have an active membership.
- `POST branches/` — system administrator only.
- `GET/PATCH branches/{id}/` — system administrator only for settings; non-admins can retrieve only assigned branches.
- `DELETE branches/{id}/` — prohibited; deactivate instead.

## Courses
- `GET courses/` — catalogue. Optional query parameters: `search`, `status`.
- `POST courses/` — system admin or staff with branch-manager/admissions membership.
- `GET/PATCH courses/{id}/` — authenticated staff with suitable access; students/non-staff see active courses only.
- `DELETE courses/{id}/` — converted into archive action, never physically deleted.

## Audit
- `GET audit/` — system administrator only; read-only.
- `GET audit/?action=course.update` — filter by action.

Pagination uses DRF page-number pagination. Errors use standard DRF JSON responses. More endpoints are added with each milestone.


## Students, admissions and enrollments — Phase 2A
All endpoints below require JWT authentication and are restricted to the user's active branch memberships.

### Students
- `GET students/` — list accessible students; optional `search` and `status` filters.
- `POST students/` — create a student in a branch where the user has Branch Manager or Admissions Officer access.
- `GET/PATCH students/{id}/` — retrieve/update an accessible student.
- `DELETE students/{id}/` — prohibited; retain records and update status.

### Admissions
- `GET admissions/` — list accessible applications; optional `search` and `status` filters.
- `POST admissions/` — create an application for an active course and an accessible branch.
- `POST admissions/{id}/review/` — body `{"status":"under_review|accepted|rejected|withdrawn","review_notes":"..."}`.
- `POST admissions/{id}/convert/` — converts an accepted application once into a student and pending course enrollment.
- `GET/PATCH admissions/{id}/` — retrieve/update an application; converted applications are locked.

### Enrollments
- `GET enrollments/` — list accessible enrollments; optional `search` and `status` filters.
- `POST enrollments/` — create an enrollment for a student and active course in the student's own branch.
- `GET/PATCH enrollments/{id}/` — retrieve/update an enrollment.
- `DELETE enrollments/{id}/` — prohibited.

Branch Managers and Admissions Officers can write records in their assigned branches. Finance Officers, Instructors and Read-only Staff have read access. System administrators can access all branches. Student, application and enrollment reference numbers are generated by the server. All create, update, review and conversion operations are audit logged.
